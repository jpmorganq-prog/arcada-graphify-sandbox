## Независимая динамическая проверка

На изолированной копии четырёх исходных файлов (`src/pricing.mjs`, `src/tax.mjs`, `src/invoice.mjs`, `test/invoice.test.mjs`) команда `git hash-object` вернула Git blob SHA, совпадающие с GitHub для каждого файла на индексированном коммите.

1. Исходный вариант: `node --test test/invoice.test.mjs` → **1 PASS, 0 FAIL**.
2. Контролируемая искусственная мутация **только временной копии**: вместо `return Math.round(subtotal * rate * 100) / 100;` записано `return subtotal * rate;`.
3. Тот же тест → **0 PASS, 1 FAIL**: `tax: 2.9000000000000004` вместо `tax: 2.9` (`ERR_ASSERTION`).
4. Никаких изменений в GitHub, ARCADA, Neon или Render при мутации не выполнялось.

**Разграничение:** Graphify обнаружил структуру вызовов, но не тестировал исполняемый код и не находил ошибку сам. Ошибку обнаружил динамический тест Node.js.

## Вывод и условия для ARCADA

- **Полезно:** быстро выявлять связанный код, путь вызовов, критические входы, предварительный список файлов и тестов, наглядно объяснять структуру.
- **Ограничение:** граф — статический срез одного коммита; возможны неточные приоритеты и пропущенные косвенные тесты. `tests=[]` **не равно** «нет тестирования».
- **Обязательный контроль:** перед работой сравнивать индексированный commit с текущим, сверять результаты с исходниками, выполнять реальные тесты и проверку прав; не использовать `impact_and_risk` как решение о безопасности/приёмке.
- **Безопасность:** реальный закрытый код ARCADA не передавать в Graphify Cloud без отдельной оценки и разрешения; публичный sandbox не содержит коммерческих данных.
- **Экономия токенов / ускорение больших задач / масштабируемость:** этим экспериментом не подтверждены.

**Следующее решение:** продолжить с локальным Graphify на изолированной копии закрытого проекта, если появится проверенная среда установки; облачную индексацию приватного репозитория не выполнять автоматически.
